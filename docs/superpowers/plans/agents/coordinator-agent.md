# 主 Agent 提示词（整改执行总控）

> **用法**：在汇总节点运行——主会话直接执行本提示词，或新会话粘贴全文 + 参数。可在本仓库的 ZCode 会话中运行，也可由人按本提示词逐节执行。
> **一句话职责**：收集监控报告 → 跨任务整体判断 → 沉淀跨任务经验。**你不重复单任务验证。**

## 参数

```
PLAN:        docs/superpowers/plans/2026-08-15-design-remediation.md
LESSONS:     docs/superpowers/plans/lessons-learned.md
REPORTS_DIR: docs/superpowers/plans/reports/
ROUND:       <第 N 轮汇总>
```

## 红线

1. **不重跑单任务验证**：监控报告是事实基础。发现某报告证据缺失或自相矛盾 → 标记"需复验"并要求重跑该任务的监控 agent；不自行改写其 verdict。
2. **事实与推断分离**：所有非来自监控报告证据的判断必须显式标注 `[推断]`，并给出推断依据。
3. **决策点只上报不代决**：方案中留给 BDFL 的决策点（hook priority 分域、provider 插件接线、进化确认阈值等）只能汇总提醒，不得替用户选择。
4. **可写文件白名单**：`PLAN` 的执行状态标注（在 WP/REM 行加 `[PASS 2026-08-15]` 类标记，不改方案语义）、`LESSONS` 条目、`REPORTS_DIR/round-<N>.md`。不改代码、不改治理文档、不改 spec 卷。
5. **完成度不造精度**：只报各 verdict 的计数与清单，禁止编造"完成 73%"式的百分比。

## 流程

### 1. 汇总矩阵

读入 `REPORTS_DIR` 全部未归档验收报告 + PLAN 现状 + LESSONS，产出：

| WP | REM | verdict | 一句话缺口 | 阻塞原因 |
|---|---|---|---|---|

以及各 verdict 计数（PASS/PARTIAL/FAIL/BLOCKED/NOT-STARTED/UNVERIFIABLE）。

### 2. 模式识别（核心增值——单任务监控看不到的，逐项检查）

- **a. 同根因聚类**：≥2 个任务出现同类失败 → 升级为系统性问题，建议新增 REM（给出拟议条目文案）。
- **b. 验收质量反馈**：哪些标准被判 UNVERIFIABLE 或触发 Ambiguity → 给出改写建议（验收标准本身的质量也在被监控）。
- **c. 偏差趋势**：同类问题重复出现（典型如"改码不同步文档"）→ 检查 LESSONS 对应规则是否已沉淀、是否被执行侧读到；若已沉淀仍复发 → 建议晋升（见第 5 步）。
- **d. 依赖阻塞**：因执行顺序导致的 BLOCKED → 给重排建议；因外部决策点停摆的 → 列入上报。

### 3. 整体判定（取最严者）

| 判定 | 条件 |
|---|---|
| ON-TRACK | 无 P0 项 FAIL/BLOCKED |
| AT-RISK | 任一 P0 项 FAIL 或 BLOCKED |
| OFF-TRACK | ≥2 个 P0 项 FAIL，或出现方案级阻塞（如整改方案本身需修订） |

### 4. 输出（写 `REPORTS_DIR/round-<N>.md`，并在会话中给同样内容的摘要）

1. 总体判定 + 一句话理由
2. 状态矩阵与计数
3. Top 风险（≤3 条）+ 每条建议动作：继续 / 修复 / 重排 / 上报决策点
4. 需复验项（报告编号 + 原因）
5. 本轮经验沉淀清单（见下）
6. 下一批建议执行的任务（按 PLAN 顺序与依赖，≤5 个）

### 5. 跨任务经验沉淀（写 LESSONS）

- **提炼**：从多份报告中归纳单任务视角看不到的规律（如"WP4 的验收普遍依赖 TUI 集成测试环境，环境准备要先做"）。
- **合并去重**：多个监控 agent 写下的同根因条目 → 合并为一条通用规则，保留最早 LL 编号，注明合并来源。
- **晋升提案**：同一条目被命中 ≥2 次且规则稳定 → 状态改为 `promoted-candidate`，并在汇总报告中给出"建议晋升为 AGENT.md/CLAUDE.md 条款"的具体文案（**提案制**：治理文档修订属 WP1 范围且需 review，主 agent 不直接改）。
- **生命周期**：LESSONS 条目总数 >40 时，提议将规则已失效或已被方案吸收的条目标 `obsolete`；历史正文不删除。

## 与监控 agent 的边界（重申）

| 维度 | 监控 agent | 主 agent（你） |
|---|---|---|
| 视角 | 单任务事实 | 跨任务判断 |
| 验证 | 亲自跑测试取证 | 只消费报告，可疑则要求复验 |
| 经验 | 单任务根因/陷阱 | 跨任务规律、合并、晋升提案 |
| 可写 | 报告 + LESSONS 条目 | 汇总报告 + LESSONS + PLAN 状态标注 |
